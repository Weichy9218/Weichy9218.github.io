POST-TRAINING | DISTILLATION

OPD 为什么比 RL 省算力，以及何时失效

2026-05-27 | 结合 Thinking Machines Lab 报告、RLHF Book 与 Rethinking OPD 整理

现代大语言模型的训练通常划分为三个阶段：Pre-training 负责通用语言能力、宽泛推理与世界知识；Mid-training 负责注入领域知识（代码库、医学语料、企业内部文档）；Post-training 则把已有能力塑造成目标任务所需的行为模式（指令遵循、数学推理、工具调用、多轮对话）。

长期以来，后训练的两大主流做法 SFT（含 Off-policy 蒸馏）和 On-policy RL 各自只占了一半优势。On-Policy Distillation（OPD）把「学生自采样」和「逐 token 密集监督」拼在一起，显著压缩了算力成本，但它同样有明确的失效前提。

1. 后训练二维象限：为什么 Off-Policy SFT 会在长程任务上漂移？

后训练的核心决策可以拆成两个正交维度：轨迹从谁的分布采样（Off-policy vs. On-policy），以及监督信号有多密（Sparse vs. Dense）。

后训练范式 采样来源 监督密度 对应优化方向 典型瓶颈
SFT / Off-Policy Distillation 外部轨迹（Teacher / 人类 / 固定数据集） Dense（每个 token 有交叉熵监督） Forward KL：$D_{\text{KL}}(\pi_T \| \pi_S)$ 长程任务曝光偏差（Exposure Bias）；易模仿语气而非事实准确性
On-Policy RL（RLHF / RLVR） Student 自己 rollout Sparse（整条轨迹仅末端 1 个标量 reward） 序列级 Reverse KL 正则化 信用分配极难，样本效率低、算力开销大；奖励模型易被 hack
On-Policy Distillation (OPD) Student 自己 rollout Dense（Teacher 对每个 token 实时打 logprob） Token 级 Reverse KL：$D_{\text{KL}}(\pi_S \| \pi_T)$ 受限于 Student 的初始 Support 与师生 Thinking Pattern 一致性

1.1 为什么 Off-Policy SFT / 蒸馏会在长程任务上失灵？

普通基于 Teacher 样本的 SFT，本质上是全分布蒸馏的蒙特卡洛无偏估计：

$$\mathbb{E}_{y \sim p_T}[-\log p_S(y)] = -\sum_{y} p_T(y) \log p_S(y)$$

但在推理与多轮 Agent 任务上，Off-Policy 蒸馏存在两类顽疾：

  1. 分布漂移与级联错误（Compounding Error）：训练时 Student 看到的永远是 Teacher 的「完美前缀」；一旦推理时 Student 在早期走错一步，进入了 Teacher 轨迹从未踏足的状态，它没学过如何从自己的错误状态里修正回来，后续轨迹越偏越远。
  2. 模仿风格而非能力（Style over Factuality）：单纯拟合 Teacher 输出，小模型很容易学会强模型的自信语气、排版套路与推理模板，却没有真正掌握背后的事实准确性与判断逻辑。

2. Reverse KL 如何把 Teacher 分布变成逐 Token 奖励？

OPD 的实现极为简洁：先让 Student 策略 $\pi_\theta$ 像 RL 一样自己 rollout 出完整轨迹 $x = (x_1, \dots, x_L)$，然后把同一条轨迹同时送入 Student 和冻结的 Teacher $\pi_{\text{teacher}}$ 做一次前向评分（Teacher 不负责续写，只给 Student 已生成的每个 token $x_{t+1}$ 打对数概率）。

核心优化目标是最小化 Reverse KL 散度：

$$D_{\text{KL}}\bigl(\pi_\theta \,\|\, \pi_{\text{teacher}}\bigr) = \mathbb{E}_{x \sim \pi_\theta}\!\left[\sum_{t} \Bigl(\log \pi_\theta(x_{t+1} \mid x_{1:t}) - \log \pi_{\text{teacher}}(x_{t+1} \mid x_{1:t})\Bigr)\right]$$

2.1 Forward KL vs. Reverse KL：方向反过来意味着什么？

KL 散度严格不对称：$D_{\text{KL}}(P \| Q) \neq D_{\text{KL}}(Q \| P)$。

  • Forward KL $D_{\text{KL}}(\pi_T \| \pi_\theta)$（普通 SFT / Off-policy 蒸馏）：期望取在 Teacher 分布上。只要 Teacher 会生成某种写法，Student 就被迫给它分配足够概率，因此表现为 Mode-covering（覆盖所有模式），小容量模型容易在多个模式之间平均分配概率，产生模糊或幻觉输出。
  • Reverse KL $D_{\text{KL}}(\pi_\theta \| \pi_T)$（OPD）：期望取在 Student 自己采样的分布上。只要 Student 落进 Teacher 认可的某一个高概率模式里，就不会因为没覆盖 Teacher 的其他解法而受罚，因此表现为 Mode-seeking（聚焦高概率模式），对参数量受限的小模型格外友好。

2.2 逐 Token 奖励与具体数值直观

把每一步的 Reverse KL 样本项取负号，就得到直观的 per-token reward / advantage：

$$r_t = \log \pi_{\text{teacher}}(x_{t+1} \mid x_{1:t}) - \log \pi_\theta(x_{t+1} \mid x_{1:t})$$

注意这是对数概率差（等价于概率比值的对数），不是直接做概率减法：

  • 严厉惩罚「自信胡说」：若 Student 以 $p_S = 0.8$ 的高置信度生成 token $A$，但 Teacher 认为 $p_T = 0.02$，则单步 KL 损失 $\log(0.8 / 0.02) = \log 40 \approx +3.69$，对应强负奖励 $r_t \approx -3.69$，立刻压低该错误 token 的概率。
  • 强化「不够自信但正确」的采样：若 Student 只给了 $p_S = 0.1$ 就采到了 token $B$，而 Teacher 给出 $p_T = 0.5$，则单步损失 $\log(0.1 / 0.5) = \log 0.2 \approx -1.61$，对应正向优势 $r_t \approx +1.61$，推动 Student 提高它的生成概率。

3. OPD 的四个关键性质：零折扣、RL 同构、抗作弊与模式聚焦

3.1 折扣因子 $\gamma = 0$（只管当下这一步）

标准 RL 的累计回报是 $R_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \dots$。但在 OPD 中，Thinking Machines 的实验发现设置 $\gamma > 0$ 并没有带来收益，因此直接取 $\gamma = 0$（即 $R_t = r_t$）。每个 token 的更新只取决于当前步 Teacher 的即时对数概率评价，方差极小且不把后续噪声反向传回来。

3.2 与现代 RL 框架天然同构（Natural Synergy with RL）

带 KL 正则的标准 RLHF / RLVR 目标为：

$$\max_{\pi_\theta}\; \mathbb{E}_{y \sim \pi_\theta}\bigl[r(x, y)\bigr] - \beta\, D_{\text{KL}}\bigl(\pi_\theta \,\|\, \pi_{\text{ref}}\bigr)$$

如 RLHF Book 所总结的，最大化该目标在数学上等价于最小化朝向最优诱导策略 $\pi_\star$ 的 Reverse KL。工程上，RL 是「Student rollout → 序列级 reward → 策略梯度更新」，OPD 则是「Student rollout → Teacher logprob 给出 per-token advantage → 复用完全相同的 RL 策略梯度训练管线」（如 tinker-cookbook 中的实现），几乎零改造成本就能和 RLVR 混训或串联。

3.3 抗 Reward Hacking（Unhackable 的准确边界）

独立训练的标量 Reward Model 容易被策略利用漏洞（凑字数、装自信、刷格式）。OPD 没有独立的判别器，奖励直接来自 Teacher 自身的生成对数概率分布：Student 想拿到低 Reverse KL，在数学上就必须在自己常采样的区域里逼近 Teacher 的条件分布，不可能找到一个「Teacher 给出极低概率但奖励很高」的漏洞。需要澄清的是，unhackable 不等于绝对正确：如果 Teacher 本身在某题上会犯错，Student 仍会学到 Teacher 的偏见。

3.4 样本高效与多轮复用不塌缩

稀疏结果奖励 RL 在同一批 prompt 上反复训练极易过拟合答案；而 OPD 的监督目标是整个条件 token 分布，哪怕对少量 prompt 做多轮不同 rollout 复用，只要 Student 采样出的路径不同，Teacher 就能持续提供全新的密集纠错信号。

4. 实验证据：惩罚分叉 Token，用约 1/10 RL 算力推高 AIME 与行为恢复

4.1 核心机制现象：惩罚集中在「分叉 Token」

把 OPD 在一条错误推理轨迹上的逐 token Reverse KL 画出来，可以观察到一个明确规律：错误结论通常由前文少数关键推理分叉引发，后续步骤只是沿错误前提推演的自然结果。

配合 $\gamma = 0$，OPD 直接把梯度指向第 $t$ 步出错的前提判断（「把现实问题当成纯算术题、忽略了冰块会融化」），而不仅是在结尾给出对错标记。放到多轮工具调用 Agent 里同理，最有信息量的更新落在中间决策分叉点：本该先调用搜索却直接作答、本该核对 observation 却视而不见、本该收尾却陷入死循环。

4.2 定量对比：数学推理（AIME'24）与企业知识个性化

实验场景 基座与训练流程 核心定量结果与结论
数学推理（AIME'24） Qwen3-8B-Base 先用 400K OpenThoughts-3 样本做 Off-policy SFT 冷启动，再以更大模型（如 Qwen3-32B）为 Teacher 做 OPD Off-policy SFT 停留在 ~60%；传统稀疏奖励 RL 推到 67.6%–70% 需约 17,920 GPU 小时；OPD 仅用约 1/10 的算力（~1,800 GPU 小时）即推至 70%。
领域个性化 / 持续学习 Stage 1：用企业内部文档对 Student 做 Mid-training（注入私有知识，但破坏了原有助手行为）；Stage 2：以旧版 Qwen3-8B 为 Teacher，在通用 Tulu3 prompts 上做 OPD 关键误区澄清：OPD 阶段完全没碰内部文档，它的作用不是「教新知识」，而是在不遗忘新学内部知识的前提下，以极少步数（比 RL 少 7–10×）无损恢复指令遵循与助手交互行为。

对后训练与持续学习的四条架构分工

  1. RL 是昂贵的策略搜索器：用于探索超越任何已有 Teacher 上限的新解。
  2. OPD 是高效的策略复制器：只要已有更强 Teacher，OPD 在同精度下可把算力压到 RL 的约 1/10。
  3. OPD 比 SFT 更适合行为保持：Reverse KL 只约束 Student 自身访问到的区域，不易冲刷掉刚学到的领域权重。
  4. 持续学习的合理分工：用 Mid-training / SFT / RAG 注入新知识，再用 OPD 快速恢复通用对话、工具格式与成本控制行为。

5. OPD 何时会失效：Support 缺失、思维模式冲突与两阶段配方

OPD 并不是「拿任意弱 Student 配一个强 Teacher 就能直接见效」的方案。结合 Thinking Machines 的实验前提与 Rethinking On-Policy Distillation of Large Language Models（arXiv:2604.13016）的机制分析，OPD 的成败严格受限于两个前提：

5.1 Support 缺失：采不到就永远学不会

因为 OPD 是纯粹 On-policy 的，奖励只计算在 Student 实际采样出来的 token 上。如果某个正确动作（例如调用 call_tool(search)）在 Student 当前策略下的概率几乎为零、rollout 中根本采不到，那么 OPD 只能不断惩罚「直接瞎答」，却没有机会给 call_tool(search) 赋予正优势。换句话说，OPD 无法从零凭空创造 Student 分布支撑集之外的新能力。

5.2 Thinking Pattern 一致性（跨家族强 Teacher 未必更好）

Rethinking OPD 指出，OPD 成功除了要求 Teacher 能提供真实的信息增益（Information Gain），还强依赖师生思维模式兼容（Thinking-Pattern Consistency）：在 Student 访问到的状态上，师生必须共享一小撮承载 97%–99% 概率质量的核心候选 token。

如果 Teacher 习惯「先列物理前提再建方程」，而 Student 只会「见数就加减乘除」，即使 Teacher 纸面分数再高，它在 Student 诡异前缀上打出的 logprob 也会充满高方差噪声。工程上，一个同家族、同工具接口、同推理风格的 Teacher，往往比一个异构但纸面更强的超大 Teacher 有效得多。

5.3 实践中最稳的两阶段配方

回头看 Thinking Machines 的两个主实验，其实都遵循了同一套两阶段工程范式（arXiv:2604.13016 也给出了相同的补救方案：Off-policy Cold Start + Teacher-aligned Prompt Selection）： 

Stage 1 | Off-Policy SFT / Mid-training（铺开 Support 与注入知识）
  └─ 例：400K OpenThoughts-3 SFT 让 Qwen3-8B-Base 达到 AIME'24 60%
  └─ 或：内部文档 Mid-training 让模型掌握领域知识

Stage 2 | On-Policy Distillation（在已有 Support 上做密集修正与行为塑形）
  └─ Student 自主采样 rollout，同构 Teacher 逐 token Reverse KL 打分
  └─ 消除长程曝光偏差，低成本把 AIME'24 推至 70% / 恢复助手行为

总结 OPD 的定位：它无法从零建立分布之外的新能力，但在 Student 已具备基础 Support 后，能以低算力和低遗忘的方式把策略分布对齐到 Teacher 的高概率区域。
