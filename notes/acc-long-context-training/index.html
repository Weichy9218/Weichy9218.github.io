AGENT TRAINING | LONG CONTEXT

为什么多轮 Agent SFT 学不好长上下文

2026-05-27 | 拆解 Attention/Loss Mask、监督盲区与 ACC（Su et al., USTC & Shanghai AI Lab）

多轮工具交互 Agent 在解题时动辄产生几万到十几万 token 的轨迹，里面散落着网页正文、代码文件和数据库表片段。按直觉，直接拿这些长轨迹做标准 Agent SFT，模型应该自然越训越擅长长上下文推理；但实验事实恰恰相反，直接拿原始 Agent 轨迹做 SFT，甚至会让模型的长程依赖推理能力倒退。

这篇笔记先从容易混为一谈的 Attention Mask 与 Label/Loss Mask 机制切入，量化拆解多轮 Agent SFT 的监督盲区，再精读 ACC（Agent Context Compilation）的方法设计、MRCR / GraphWalks 定量实验、消融与 MoE 机制分析，最后给出对方法归因边界的保留意见。

1. Attention Mask 与 Loss Mask：多轮 SFT 的监督权重如何被稀释？

对任意 Decoder-only 语言模型，标准自回归训练目标可以统一写为带掩码的交叉熵：

$$\mathcal{L} = -\sum_{i} m_i \log P_\theta(x_i \mid x_{<i})$$

工程实现里存在两类完全不同的 mask，理解 Agent SFT 为什么学不到长上下文整合，必须先分清这两者：

  • Attention Mask（控制「能不能看见」）：作用在前向注意力矩阵上。除了自回归天然的因果下三角 mask 外，真实 token 的 attention_mask = 1、padding 为 0。在标准 Agent SFT 中，工具返回的 observation 不会被 attention mask 遮掉，后续 assistant token 完全可以 attend 到它。
  • Label Mask / Loss Mask（控制「算不算 loss」）：不影响前向可见性，只把不希望模型去「复述生成」的位置设为 labels = -100（即 $m_i = 0$，被 PyTorch CrossEntropyLoss(ignore_index=-100) 跳过）。因为网页内容或 SQL 返回结果应由外部环境提供，标准 Agent SFT（常称 assistant-only / completion-only loss）只对 assistant 自己生成的 reasoning、tool call 与 final answer 计入损失。

1.1 真正的问题：多轮轨迹下的 Loss 权重严重失衡

把一条 $k$ 轮 Agent 轨迹记为 $\tau = \bigl(q, (r_1, a_1, o_1), \dots, (r_{k-1}, a_{k-1}, o_{k-1}), (r_k, y)\bigr)$。标准 Agent SFT 的损失为：

$$\mathcal{L}_{\text{agent}} = -\sum_{t=1}^{k} \sum_{j \in \mathcal{I}_t} \log P_\theta(\text{token}_j \mid \mathcal{H}_{<t}, \text{token}_{<j}), \qquad \mathcal{I}_t = \begin{cases} r_t \cup a_t, & t < k \\ r_k \cup y, & t = k \end{cases}$$

问题并不在于「模型看不见 $o_t$」，而在于绝大部分有梯度的监督 token 被稀释在了中间步骤的动作模仿上。算一笔账：假设一条轨迹经过 20 轮工具调用，每轮 assistant 输出 100 token 的思考与工具调用参数，最后总结输出 50 token 的最终答案。整条样本里有 2,000 个 token 在训练「当前状态下一步调什么工具」（local policy imitation），只有 50 个 token（2.4%）在训练「把第 1、3、7 轮里散落的证据拼起来得出结论」（global evidence integration）。

这就是论文指出的 Supervision Blind Spot（监督盲区），也是整篇论文动机里最站得住脚的核心观察。

2. ACC 如何把多轮工具轨迹编译成静态长上下文问答？

ACC（Agent Context Compilation）的解法非常直接：与其花重金人工标注长文档或启发式拼接伪长文本，不如直接复用 Agent 运行时天然产出的海量真实工具轨迹，把多轮交互轨迹离线「编译」成单轮静态长上下文问答样本 $(q_i, C_i) \to (r_i, y_i)$。

2.1 三类环境覆盖与核心编译步骤

作者将 ACC 应用到三种结构迥异的 Agent 轨迹，共编译出 10,802 条长上下文训练样本（最大序列长度 131,072 tokens）：

  • Search Agent（$n = 3,369$）：网页搜索结果与访问正文，对应开放域非结构化长文本。
  • SWE Agent（$n = 4,368$）：代码仓库文件内容与调试日志，对应多文件代码结构。
  • SQL Agent（$n = 3,065$）：数据库表内容与查询结果，对应离散关系结构。

构造每条编译样本包含三个关键设计：

  1. 纳入真实干扰项（Distractors）：除了保留 Agent 真正访问过的证据片段，还会刻意混入同一轨迹里出现过但未采纳的搜索结果或未打开的代码文件，迫使模型在数万 token 噪声中学会筛选与定位。
  2. 随机打乱片段顺序（Shuffling）：把所有证据与干扰项随机重排拼成 $C_i$，消除「顺着 Agent 探索的时间顺序直接抄最后几段」的顺序捷径，逼迫模型依靠语义匹配做跨段关联。
  3. 合成经验证的推理链 $r_i$：在几万 token 上下文里如果只监督最终几个词的答案（如 Les Tzars），监督信号依旧过于稀疏。作者使用 DeepSeek-V3.2-Thinking 基于 $(q_i, C_i)$ 生成候选推理过程与答案，仅保留最终答案严格匹配真实标签 $y_i$ 的样本。不同领域的合成通过率差距明显：Search 接近 100%，SQL 约 50%，SWE 仅约 10%，复杂代码任务的推理链合成构成了实际扩展瓶颈。

具体编译样例（Search Agent | Les Tzars）

原始多轮轨迹中，Agent 分 3 轮搜索并依次访问了 [Doc A]（黑金属翻唱欧洲加曲）、[Doc D]（1994 广播现场 5 分钟版）、[Doc G]（1997 精选盘 Disc One 第三首），期间还夹杂了无关网页 [Doc C]。ACC 删掉所有中间搜索指令，把 [Doc G, Doc C (distractor), Doc A, Doc D] 乱序拼成单轮上下文 $C_i$，并要求模型直接输出跨文档定位推理链 $r_i$ 与最终答案 Les Tzars。

3. 实验验证：30B 追平 235B，且原始 Agent SFT 反而倒退

作者以 Qwen3-30B-A3B-Thinking（总参 30B、激活 3B 的 MoE 推理模型）为基座，使用标准 SFT 训练 4 个 epoch（序列长度 131,072、global batch size 16、AdamW、初始学习率 $1\times 10^{-5}$ 余弦退火至 $1\times 10^{-6}$、序列并行度 8）。主评测聚焦两个专门检验长程依赖建模的硬基准：

  • MRCR（Multi-Round Coreference Resolution）：在一堆高度相似、极易混淆的多轮对话中精准找回「第 $k$ 次出现的那个对象」，测的是长上下文精确定位与消歧。
  • GraphWalks（BFS & Parents）：把超长上下文当成一张显式图，要求从起点返回指定深度可达节点（BFS）或全部入边父节点（Parents），测的是跨位置多跳关系推理。

与现有专门的长上下文后训练方法相比（Table 5）：QwenLong-L1.5-30B 动用了文档清洗 + 知识图谱构建 + RL 的复杂多阶段流水线，在 MRCR 上领先（92.30 vs 68.28），而 ACC 仅靠纯 SFT 就在 GraphWalks 上反超它（77.51 vs 73.85），大幅高于 LongRLVR（15.72 / 22.78）与 LongPO（12.97）。

Table 6 显示了三条关键规律：

  1. 验证监督盲区：直接用原始 Search 轨迹做 Agent SFT，MRCR 下降 8.03 分，GraphWalks 下降 12.05 分；单纯把长轨迹塞进标准 SFT 不仅无益，反而伤害长程依赖建模。
  2. 数据结构决定任务迁移方向：三类单源编译数据都能拉升 MRCR，但到了 GraphWalks 上，只有 SQL 提升（+5.58），单用 Search 或 SWE 反而下降 25.17 与 19.26 分。因为网页与代码是连续长段落，而 SQL 表格天然具备离散关系与外键连接结构，更匹配图遍历推理；三者混合后彼此互补，双指标达到全局最高。
  3. 干扰项的双向作用：去掉 Search / SWE 的 distractor 会让 MRCR 分别下降 3.34 和 3.81 分，证明干扰项对「抗噪精确定位」至关重要。

4. 内部机制与归因边界：注意力重构、MoE 特化与未解耦的蒸馏增益

4.1 Attention 重构与 MoE 专家特化

作者对比了训练前后模型在两个任务上的注意力距离分布与 MoE 专家路由频率，发现模型内部确实演化出了任务自适应的分工：

  • GraphWalks：注意力质量在近距离和超远距离区间双双增强，同时远距离 token 的 MoE 路由分散激活到多个专家，对应跨节点多跳推理的均衡协作。
  • MRCR：注意力主要在局部近邻扫描与核对区间增强，同时 MoE 路由高度集中到少数专用专家（其余专家被抑制），且两类任务激活变化最剧烈的网络层完全不同。

4.2 读完后必须保留的两点清醒判断

ACC 真正证明了什么，以及还没拆干净什么

  1. ACC 训练出的是更强的静态长上下文推理器，不是通用 Agent Policy：评测集 MRCR 和 GraphWalks 本身就是单轮静态长上下文任务，评测时不需要 ACC 编译；它证明的是「Agent 轨迹日志本身就是低成本的长上下文训练数据来源」，而如何把这种长上下文证据整合能力反哺回多轮交互式 Agent 策略（例如与标准 Agent SFT / RL 混训），论文尚未验证。
  2. 两个增益来源没有完全解耦：ACC 带来的 +18.09 / +7.59 提升，实际上叠加了（a）Compiled Context Supervision（把监督直接锚定到跨段证据上）与（b）强 Teacher（DeepSeek-V3.2-Thinking）的 Rationale Distillation。论文没有做「同等 teacher 生成无编译对照」的消融来把两者的贡献分开验证，因此在评估纯数据编译贡献时需要保留余地。
